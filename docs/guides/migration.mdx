# 数据与后端迁移

## 迁移前检查

先备份 `local_db.json`、本地对象目录和企业目录，记录文件数、总字节和抽样 SHA-256。确认目标后端容量、生命周期、版本控制和凭据权限，停止不必要的写流量或启用一致的迁移窗口。

检查清单：

- `DATA_DIR` 可读写，磁盘至少容纳临时分片和数据库备份。
- 源与目标健康检查通过。
- 生产秘密通过 Secret 注入，迁移日志不包含连接串。
- 已定义回滚、失败重试和源数据保留策略。
- 多副本写流量不会绕过迁移锁。

## 元数据迁移

```bash
npx tsx scripts/migrate.ts status
npx tsx scripts/migrate.ts up
npx tsx scripts/migrate.ts down 001
```

迁移脚本按版本记录执行状态，使用事务和幂等步骤。`down` 只能撤销明确支持回滚的迁移；涉及破坏性字段删除或外部对象操作时，应通过前向修正而不是假装可以无损回滚。

旧公开和私密记录保留兼容格式。企业记录额外保存后端名称、校验和、扫描状态、租户和下载计数。不要在没有映射策略时批量赋予不同租户，否则可能造成越权。

## 跨后端对象迁移

```bash
npx tsx scripts/storage-migrate.ts
```

`StorageMigrator` 通过分页列举源对象，以有界并发流式复制，比较源元数据、输出大小和重新计算的 SHA-256。游标重复或不前进会停止迁移，防止死循环和遗漏。

默认保留源对象。只有复制和校验全部成功后，才在独立清理阶段设置 `deleteSource`。单个对象失败计入失败数，不应被总体进度百分比掩盖。

## 断点与恢复

迁移中断后先读取失败清单，再按对象 ID 和摘要决定重试。目标中已有但摘要不符的对象不能简单跳过，应进入冲突处理。网络超时后不要假设目标上传未完成，需要先查询目标状态。

大型 multipart 上传失败应中止临时上传，避免云平台持续计费。IPFS 迁移还要持久化新的 ID→CID 映射，不能只复制目录记录。

## 切换与回滚

1. 在预发布环境执行全量迁移和抽样下载。
2. 对目录中全部对象比较数量、大小和摘要。
3. 运行扫描、Webhook、审计和过期清理回归。
4. 小比例切换读流量，观察错误率和延迟。
5. 切换写流量并继续保留源数据。
6. 稳定后再安排独立源清理。

回滚时优先把路由切回仍然完整的源后端。若切换期间目标已接受新文件，需要先反向同步差异，不能直接用旧备份覆盖新状态。

## 验证报告

迁移报告至少包含开始/结束时间、源目标类型、总数、成功、失败、跳过、重试、字节数、摘要失败对象和操作人。报告进入审计系统，敏感对象 ID 按合规要求脱敏。
