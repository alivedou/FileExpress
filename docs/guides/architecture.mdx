# 架构与数据流

## 模块边界

- `src/storage`：统一后端、注册表、路由、故障转移、目录和迁移。
- `src/upload`：Tus、自研分片、会话锁、摘要和恢复。
- `src/security`：扫描引擎、聚合队列和隔离区。
- `src/drm`：DCT 水印、可见渲染、策略与设备证明。
- `src/webhooks`：事件信封、传输总线、可靠投递和转发器。
- `src/auth`：团队、角色、API Key 和 Express 授权中间件。
- `src/audit`：追加式存储、签名链、归档与 SIEM 导出。
- `src/observability`：指标、日志、追踪和告警。
- `src/api`：Express 企业路由及跨模块编排。

后端适配器通过接口注入，单元测试不需要真实云服务。Express 继续作为主服务框架，React、Tailwind 与 Framer Motion 构成前端。

## 上传数据流

```text
Browser → Tus/Chunks → Session lock + checksum → Storage registry
        → Persistent catalog → Upload event → Scan queue
        → Clean / Review / Quarantine → Download authorisation
```

合并完成和对象持久化必须区分临时会话与正式对象。目录记录保存实际后端名称，因此故障转移后下载仍从成功后端读取，而不是再次经过可能不同的路由。

## 一致性边界

本地目录通过进程内串行化和原子文件替换保护单进程写入，不等于分布式事务。云对象上传和目录写入之间仍可能出现孤儿对象，生产需要定期对账与清理。

扫描在对象登记后异步执行，下载只接受 `clean`。扫描服务暂时不可用会留下 `pending` 或 `error`，用户看到暂不可用而不是未经扫描的内容。

Webhook 是业务提交后的事件通知，不是数据库事务的一部分。严格 Exactly-once 需要持久 outbox、投递确认和接收端幂等共同保证；当前内存总线不应被描述为事务型 outbox。

## 多租户边界

API Key 认证先确定租户和权限，再检查目标 query/body/Scope 一致性。角色权限只是授权的一层，资源查询还必须按租户过滤。管理审计由服务端写入，减少伪造入口。

自定义域名只用于团队解析，不能代替 Host 头校验和 TLS 域名校验。品牌化字段应经过长度与格式验证，避免 CSS/HTML 注入。

## 安全边界

秘密由环境或外部 Secret 注入，配置读取与错误信息脱敏。对象 ID、隔离路径、YARA 参数和 FFmpeg 参数都采用受控处理。审计签名链可检测修改，但攻击者同时拥有密钥和写权限时仍可能重建链条，因此需要外部签名和 WORM 归档。

## 扩容路径

从单实例迁移到多副本时，依次替换：共享元数据事务存储、持久事件/outbox、分布式限流、共享 DRM 计数、共享上传锁和兼容的对象/卷存储。每一步都需要故障与一致性测试，不能只增加 Deployment 副本数。

## ADR

`docs/adr` 记录存储抽象、流式续传和审计完整性等决策。新增重大特性应记录背景、备选方案、决策、后果和回滚条件，避免只保留实现而丢失设计原因。
