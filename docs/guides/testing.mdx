# 测试与验收

## 测试层级

| 层级     | 命令                       | 依赖                             |
| -------- | -------------------------- | -------------------------------- |
| 单元测试 | `npm run test:unit`        | Node.js                          |
| 覆盖率   | `npm run test:coverage`    | Node.js 与 V8 coverage           |
| 集成测试 | `npm run test:integration` | Docker/Testcontainers 或服务容器 |
| 契约测试 | `npm run test:contract`    | Pact                             |
| E2E      | `npm run test:e2e`         | Playwright Chromium              |
| 性能     | `npm run test:performance` | k6 与运行中的服务                |
| 混沌     | `npm run test:chaos`       | 可注入故障的测试环境             |

Fixture 统一放在 `test/fixtures/`，动态数据使用 `@faker-js/faker`。测试不得使用生产凭据或向真实第三方端点发送文件。

## 覆盖率纪律

覆盖率配置要求行、函数、语句至少 90%，分支至少 85%。存储、上传、扫描、水印、DRM、Webhook、RBAC、审计和指标应通过更严格的模块评审，不能用排除核心目录的方式制造数字。

覆盖率不等于正确性。必须同时验证失败路径、并发、重复请求、进程重启、损坏元数据、跨租户访问和秘密脱敏。

## 存储与续传用例

每个后端至少覆盖：空文件、单字节、大对象、流中途失败、重复 ID、下载不存在对象、预签名过期、分页游标不前进、健康异常和配置脱敏。

Tus 覆盖创建、HEAD、顺序 PATCH、错误偏移、延期长度、创建即上传、终止和过期。分片覆盖乱序并发、重复分片、同序号不同摘要、缺失分片、最终摘要错误、完成重试和重启恢复。

## 安全与租户用例

扫描覆盖引擎超时、队列上限、恶意聚合、白名单不能覆盖恶意、隔离恢复校验和回调重放。DRM 覆盖策略缺省拒绝、CIDR、设备证明、项目不匹配和计数竞争。

Webhook 覆盖原文签名、重放、指数退避、死信和手动重发。RBAC 覆盖角色循环、跨租户 query/body、项目与桶 Scope、过期密钥和速率限制。审计覆盖追加、篡改检测、归档锚点和 CEF 注入转义。

## 真实服务集成

CI 启动 MinIO、PostgreSQL 和 ClamAV 服务。Testcontainers 测试只能在有 Docker 守护进程的环境运行，不可用时应明确跳过并报告原因，不能将未执行写成通过。

集成测试还应验证后端停止后的 readiness、故障转移创建新流、数据库事务回滚和扫描隔离。

## E2E 主旅程

完整旅程为：管理员认证→创建团队→配置 MinIO→上传大文件→中断并恢复→配置 DRM→扫描→验证下载和水印→创建 Webhook→检查监控→导出审计。

500 MiB 测试应在受控环境生成稀疏或确定性数据，避免把大 fixture 提交到 Git。下载后重新计算 SHA-256，而不是只检查 HTTP 200。

## 性能与混沌

性能测试使用混合文件大小和逐步加压，观察吞吐、P95/P99、错误率、内存和句柄。目标为 1k 并发、持续 10 分钟、P99 小于 2 秒和零请求失败；不达标必须给出环境、数据和瓶颈。

混沌测试随机停止后端和扫描引擎、注入延迟或网络错误，验证幂等、重试、故障转移和一致性。禁止对生产或共享开发环境执行破坏性故障注入。

## 验收证据

保存命令输出、覆盖率摘要、测试报告、镜像 digest、Helm/ArgoCD 状态和 cosign 验证结果。依赖缺失、命令被拒绝、外部集群不可用都必须明确列为未验收，不能用静态文件替代运行证据。
